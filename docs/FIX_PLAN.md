> 로컬 Claude Code(두들매치 Godot 소스 루트)에 그대로 먹이는 용도.
> 작성 근거: 웹 빌드 `848fed4 + 미커밋 작업 트리` (2026-10-22 16:15)의 `index.pck`를 풀어 GDScript를 복원해 읽고, 헤드리스 브라우저로 프롤로그→1판을 직접 플레이함. 비교 기준은 `chiikawa-match`(웹 프로토타입).

## 0. 작업 규칙 (먼저 읽기)

1. **`data/friends.json`, `data/economy.json`, `data/route.json` 등은 `tools/export/export.js`가 웹 프로토타입(chiikawa-match)에서 뽑아낸 파일**임 (`"generated_by": "tools/export/export.js"`). 손으로 고치면 다음 export 때 덮어써짐.
   → 이번 작업에서 바꾸는 값은 **export 대상에서 빼거나**(손관리로 전환), **두들매치 쪽 덮어쓰기 파일(예: `data/overrides.json`)을 만들어 `MetaConfig._init()`에서 머지**하는 방식 중 하나로 통일. 추천: 후자 (export는 계속 쓰고, 두들매치 고유 값만 덮어씀).
2. 판 결과가 바뀌는 수정(연쇄 순서 등)은 봇 튜닝(`data/tuned.json`, `bot*.json`) 난이도에 영향 → 수정 후 봇 클리어율 다시 재기.
3. 순서: **P0 → P1 → P2**. 각 작업은 따로 커밋.
4. 각 작업 끝나면 "완료 기준"을 실제 실행해서 확인 (웹 export 후 폰 크기 390×844에서).

## A. 보너스타임 줄이기 + 스킵/빨리감기 (P0)

### 증상
판을 깨면 보너스타임이 쓸데없이 길고, 누르거나 스킵할 방법이 없음. 치이카와 매치에 있던 스킵 수단들이 전부 빠짐.

### 원인
- `scripts/board/board_game.gd` `_bonus()`: 남은 이동만큼(최대 10) 아이템으로 바꾸고 **2개씩** `_cascade([], batch)`. 배치마다 연쇄와 낙하가 끝까지 다 돌아야 다음 배치로 넘어감.
- `scenes/board/board_view.gd` `play()`: 이벤트를 하나씩 `await`. 도는 동안 `busy = true`라서 `_gui_input()`이 입력을 전부 무시. **스킵 경로가 아예 없음.**
- `"convert"` 이벤트마다 `_wait(0.11)`, `"bonus_start"` 뒤에 `_wait(0.6)`.
- 스킬 컷인 `scenes/battle/cut_in.gd` `play()`: 0.98초 타이머와 0.24초 페이드가 고정이고 스킵이 없음.
- 설정에 "빠른 진행"이 없음.

### 참고 (chiikawa-match)
- `js/life.js` `bonus()` (716~778):
  - 배너 0.5초.
  - 로켓을 110ms 간격으로 날림.
  - 아이템은 2개씩 터뜨림.
  - **화면 아무 데나 톡 하면:** 로켓 단계에서는 남은 칸을 한 번에 아이템으로 바꾸고, 폭발 단계에서는 남은 아이템을 한 번에 터뜨림.
- `js/game.js` `FastFwd.on(x)`: 지금 도는 애니메이션, 파티클, 대기를 x배로 빨리 돌림.
  - 컷인은 두 번 톡 하면 6배.
  - 뽑기 건너뛰기는 12배.
- `Prefs.speed()`: 설정 "빠른 진행"이 켜지면 모든 대기를 1.5배 빨리.

### 할 일

1. **빨리감기 공용 장치** (`scenes/board/fx/fx_layer.gd`): `FxLayer`에 `fast_forward(rate)` / `fast_forward_end()`를 추가.
   - 이미 `stop()`과 `slow()`가 `Engine.time_scale`을 `_base_scale * _slow`로 다루니, 여기에 `_ff` 배수를 하나 더 곱하는 식으로 넣음.
   - 히트스톱(`stop`)이 빨리감기를 덮어쓰지 않게 `resume`에서 `_base_scale * _slow * _ff`로 되돌릴 것.
2. **보너스타임 스킵** (`board_view.gd`):
   - `_bonus` 중에 탭을 받는 `_skip_tap` 경로를 추가. `busy`여도 `_bonus`면 `_gui_input`에서 탭을 받음.
   - 첫 탭: `fx.fast_forward(4.0)`. 화면 아래에 "▶▶ 빨리 감는 중" 힌트를 표시.
   - 두 번째 탭(또는 길게 누르기): **남은 보너스 연출을 건너뜀.** 모델(`BoardGame`)은 이미 점수와 결과 계산이 끝났으니, `play()` 루프에서 `"bonus_end"`가 나올 때까지 `"step" / "fall" / "convert"` 이벤트는 그리지 않고 넘김.
   - 넘긴 뒤에는 남은 점수를 `float_num` 하나로 합쳐서 보여 주고, `"win"`을 처리.
   - 결과 화면은 판 그림이 필요 없으니 보드 뷰가 모델과 안 맞아도 문제없음.
3. **보너스 자체 길이 줄이기** (`board_game.gd` `_bonus()`):
   - 배치를 2개에서 **3개**로.
   - `"bonus_start"` 대기를 0.6초에서 **0.35초**로.
   - `"convert"` 대기를 0.11초에서 **0.07초**로.
   - 목표: 남은 이동 10일 때 스킵 없이 **3초 안쪽**.
4. **스킬 컷인 스킵** (`cut_in.gd`):
   - `create_timer(0.98)` 대신 탭 시그널과 타이머 중 먼저 오는 쪽으로 끝냄.
   - 아무 데나 톡 하면 바로 페이드아웃.
5. **설정 추가** (`scenes/app/settings.gd`, `AppPrefs`):
   - "빠른 진행"을 켜면 `_base_scale = 1.5`.
   - "스킬 연출"을 끄면 컷인을 생략.

### 완료 기준
- 남은 이동이 10인 판: 그대로 두면 3초 안쪽. 한 번 톡 하면 눈에 띄게 빨라짐. 두 번 톡 하면 1초 안에 결과 화면.
- 스킵해도 점수와 별 개수가 스킵 안 했을 때와 같음 (같은 씨앗으로 비교).
- 컷인 도중 톡 하면 바로 닫힘.

## B. 연쇄 폭발 순차화 (P0)

### 증상
아이템 여러 개가 맞물려 터질 때 꿈의집처럼 "펑… 펑… 펑"이 아니라 **한 번에 다 터짐**.

### 원인 (`scenes/board/board_view.gd`)
1. `_times()`:
   - 연쇄된 아이템은 시작 시각이 `base = T[그 칸이 맞은 시각]`. **연쇄 사이 간격(beat)이 없음.**
   - 퓨즈(지우개 90 / 압정 320 / 크레용 260 / 비행기 120 ms)도 첫 아이템과 똑같이 적용됨.
2. `_show_step()`:
   - 연쇄된 아이템 타일이 **맞은 순간**(`T[kk]`) 바로 `pop_item`으로 사라짐. 그래서 "다음 녀석이 부르르 떨다가 터지는" 예고가 안 보임.
   - 연쇄 단계별 효과음 음높이 상승이나 흔들림 증폭도 없음.
3. `scripts/board/board.gd` `resolve()`:
   - 연쇄 큐가 `queue.pop_back()`으로 뒤에서부터 꺼내짐(DFS). 그래서 `res.effects` 순서가 화면상 퍼지는 순서와 어긋남.
4. 히트스톱 `fx.stop()`:
   - 지우개는 40ms, 압정은 70ms 멈춤이 아이템마다 걸림.
   - 연쇄가 길면 멈칫멈칫하다가 몰아서 터지는 느낌이 됨.

### 참고 (chiikawa-match `js/game.js` `effectTimes` 1894~1926, `stepFx` 1947~2072, `chainKick` 1516~1523)
- `CHAIN_BEAT = 120`. 연쇄 아이템은 "맞은 시각 + 120ms"에 시작하고, 퓨즈는 ×0.55.
- 연쇄 아이템이 터지기 120ms 전에 `chainKick`이 붙음.
  - 연출: 찌그러졌다 펴짐 120ms + 'gooey-impact' 스프라이트.
  - 소리: 'special' 효과음, 음높이 +0.09 × 연쇄 단계 (최대 2).
- 아이템 타일은 **자기가 발동하는 순간(`fireAt`)에** 사라짐.
- 흔들림 세기는 7 + min(연쇄 단계, 4).
- 히트스톱은 100ms 미만이면 무시하고, 쿨다운이 260ms.

### 할 일
1. `board.gd` `resolve()`: 연쇄 큐를 BFS로 바꿈 (`queue.pop_front()`). 그리고 효과마다 `depth`(연쇄 단계)와 `parent`(어느 효과가 이 칸을 맞혔는지)를 기록.
   - 예: `effects.append({..., depth = depth_of[k]})`.
   - 맞힌 칸에는 `depth_of[kq] = cur_depth + 1`을 넣음.
2. `board_view.gd`에 상수 추가:
   ```gdscript
   const CHAIN_BEAT: = 140.0   # 맞고 나서 다음 아이템이 터지기까지 (꿈의집 느낌: 120~160)
   const CHAIN_FUSE: = 0.55    # 연쇄된 아이템 퓨즈 배수
   const KICK_MS: = 120.0
   ```
3. `_times()`:
   - 연쇄된 효과(`base > 0`)는 `base += CHAIN_BEAT`.
   - `fuse = FUSE[kind] * (CHAIN_FUSE if chained else 1.0)`로 칸별 시간을 계산.
   - `ef.fire = base + fuse`를 저장.
4. `_show_step()`: 효과의 원점 아이템 타일은 `delay = ef.fire`로 터뜨림 (지금은 맞은 시각).
   - 맞은 시각에는 `_chain_kick(v, depth)`를 붙임: 찌그러짐 1.0 → (1.25, 0.8) → 1.0을 120ms, 그리고 `_sfx("item_make", 1.0 + 0.09 * depth)`.
5. `_effect_fx()`:
   - 흔들림을 `4 + mini(depth, 4)` (압정은 `7 + mini(depth, 4)`)로.
   - 효과음 음높이를 `1.0 + 0.07 * depth`(최대 1.6)로.
6. 히트스톱 쿨다운: `FxLayer.stop()`에 `_last_stop_ms`를 둬서 260ms 안에 다시 오면 무시. 이렇게 하면 첫 폭발과 크게 터지는 것만 멈춤.
7. 보너스타임(A)과 연결: 빨리감기 중에는 `CHAIN_BEAT`도 같이 빨라짐 (`time_scale`로 처리되니 따로 할 일 없음).

### 완료 기준
- 지우개가 줄을 쓸다가 압정을 맞히면, 압정이 **부풀어 오르는 게 보이고** 0.1~0.2초 뒤에 터짐. 3단 연쇄면 소리가 점점 높아짐.
- 압정 + 지우개 3개가 연쇄로 걸리는 판을 녹화해서 아이템마다 터지는 시점이 눈으로 구분됨.
- 봇 클리어율 재측정 (연쇄 순서가 바뀌면 비행기 목표 선택이 달라질 수 있음).

## C. 스킬 UI 원형 게이지 + AUTO (P0)

### 증상
스킬 UI가 원형에서 막대 게이지로 바뀜. 언제 쓸 수 있는지 잘 안 보임.

### 원인
- `scenes/battle/party_slot.gd`가 그냥 `ProgressBar`(`$Gauge`)를 씀. 다 찼을 때 표시는 `$Face/Ready` 라벨 하나뿐.
- 토벌의 AUTO 버튼이 없음.
- 퍼즐(일상) 판에는 스킬 자체가 없음. 오른쪽 위 `%Helper`(`scenes/app/puzzle_stage.gd`)는 얼굴 그림만 있음.

### 참고 (chiikawa-match `css/style.css` 1055~1069, `game.js` `setGauge` 961~967, `autoSkill` 3133~3143)
- 얼굴(토벌 54px, 퍼즐 60px) 둘레를 감싸는 링. `ring_frame` 위에 `ring_fill`을 원뿔 그라데이션으로 가려서 채움. 차오를 때는 0.45초 트윈.
- 다 차면:
  - 하얀 반짝임 호가 1.3초에 한 바퀴씩 돎.
  - 분홍빛이 1초 주기로 맥박처럼 빛남.
  - 얼굴이 통통 튐.
  - 차는 순간 크기가 1.3배로 팝.
- 안 찬 얼굴을 누르면 흔들림 + 'bad' 효과음.
- AUTO: 켜 두면 게이지가 찬 스킬을 턴 끝나고 300ms 뒤에 자동 발동. 저장값 `autoSkill`.

### 할 일
1. `party_slot.tscn`: `$Gauge`를 `TextureProgressBar`로 교체하고 얼굴(`$Face`) 뒤에 겹침.
   - `fill_mode = TextureProgressBar.FILL_CLOCKWISE`.
   - `texture_under`는 링 테(손그림 연필선 느낌 원).
   - `texture_progress`는 흰 링. `tint_progress`에 속성 색을 넣음.
   - `radial_initial_angle = 0`.
   - 얼굴 지름의 약 1.25배 크기.
   - 링 이미지는 낙서풍으로 새로 그리기. 임시로는 흰 원 테두리 PNG.
2. `set_gauge(v, need)`:
   - 값은 `create_tween().tween_property(_gauge, "value", v, 0.45)`로 채움.
   - `v >= need`가 처음 되는 순간 팝(크기 1.3, 420ms) + 반짝이 효과음.
   - 다 찬 동안 `_ready_fx()` 루프: 반짝임 스프라이트 회전(1.3초), 밝기 맥박(1초), 통통 튀기.
3. 안 찼을 때 누르면 흔들림 + `AppSound` 'bad'.
4. AUTO 버튼 (`scenes/battle/battle_play.tscn` 팀 체력 옆):
   - `AppState.meta().data.auto_skill` 토글.
   - `battle_play.gd`의 턴 끝 처리에서 켜져 있으면 300ms 뒤 게이지 찬 슬롯 순서대로 `_on_skill(j)`.
5. (P1) 퍼즐 판 도우미 스킬: `%Helper`에 같은 원형 게이지를 붙이고, `BoardGame`에 게이지를 추가.
   - 게이지는 터뜨린 칸 수만큼 차고, 필요량은 토벌의 2.5배 (치이카와 `skillNeed`).
   - 스킬 효과는 `friends.json`의 `base_effects` 중 판에서 의미 있는 것(`clear_rows`, `clear_cols`, `clear_random`, `convert`, `put`)만 `board.gd`에 연결.
   - `puzzle_moves`가 있는 스킬은 "이동 +n"으로.

### 완료 기준
- 게이지가 시계 방향으로 차오르고, 다 차면 멀리서 봐도 반짝이는 게 보임.
- AUTO를 켜면 손대지 않아도 스킬이 나감. 껐다 켜도 유지됨 (저장됨).

## D. 친구 일러 크게 보기 (P0)

### 증상
친구들 창에서 캐릭터별 일러를 힘들게 뽑아놨는데 너무 작게 보이고, 눌러도 안 커짐.

### 원인
- `scenes/app/friends.gd` `open_detail()`: 카드 일러 `%CardArt`가 아래에서 올라오는 창(`%Sheet`) 안 작은 액자(`%Frame`)에만 들어감. 누르는 처리가 없음.
- 목록 타일 `scenes/app/parts/friend_tile.gd`도 `%Art`에 스티커를 작게 보여 줌.

### 할 일
1. **전체 화면 일러 보기** (새 장면 `scenes/app/parts/art_viewer.tscn`):
   - 검은 배경 85% 위에 `card_art`를 화면에 맞춰(`STRETCH_KEEP_ASPECT_CENTERED`) 크게 표시.
   - 이름, 성, 속성은 아래쪽에 작게.
   - 열 때 크기 0.85 → 1.0으로 커지며 나타남 (`AppFx.sheet_up` 느낌).
   - 톡 하면 닫힘. 좌우로 쓱 밀면 이전/다음 친구 (가진 친구만).
   - (선택) 두 손가락 확대: `InputEventMagnifyGesture`. 웹에서는 핀치가 안 올 수 있으니 두 번 톡 하면 2배 확대로 대신.

## E. 라멘 가게 복구 (P1)

### 증상
치이카와 매치에 있던 라멘 가게(상점)가 없어짐.

### 현황

  - **화면이 없음.** `scenes/app/parts/nav_tabs.gd`의 `TABS`는 지도, 친구, 길드, 가게뿐이고, 이 "가게"(`shop.gd`)는 캡슐 뽑기와 유료 상점임.
  - 라멘 버프(한 그릇 먹기)를 적용하는 로직도 없음.

### 참고 (chiikawa-match `js/game.js` 3289~3500, `index.html` 65·81~97, `js/tutor.js` 271~279)
- 4판 깨면 열림 + 세 군데를 차례로 비춰 주는 안내.

  - 가게 주인 대사, 수행 중인 캐릭터 대사.

  - 문가에 손님 (간식 개수 뱃지). 간식을 주면 영입.
- 탭: **라멘 / 수련 / 포장**.
  - 라멘: 버프는 한 번에 하나. **토벌을 새로 깰 때마다 한 그릇 무료**, 그 외에는 코인. 5그릇마다 도장 간식.
    - 토벌 메뉴: 체력 150 / 스킬 게이지 반 / 둘 다.
    - 퍼즐 메뉴는 숨기고 포장(시작 아이템)으로 옮김.
  - 수련: 영구 체력과 공격력, 최대 Lv20, 비용 100×1.18^lv.

### 할 일
1. 진입 동선: 지도 화면에 **가게 건물 버튼**을 둠 (지도 그림 오른쪽 아래 빈 곳, 4판 전에는 잠김 표시).
   - 아래 탭이 4개로 꽉 찼으니 탭은 늘리지 않음. 더 자주 쓰게 하고 싶으면 "가게" 탭 이름을 "뽑기"로 바꾸고 "라멘" 탭을 5번째로 추가하는 것도 가능 → 지도 버튼 방식 먼저.
2. 새 장면 `scenes/app/ramen.tscn` + `ramen.gd` (`AppState.go("ramen")` 등록):
   - 배경: 낙서풍 국숫집 한 장 (임시로 길드 방 그림을 재활용해도 됨).
   - 가게 주인 NPC: 두들 세계관에 맞게 새로 지음 (예: 국물 냄새로 휘갈김을 쫓는다는 너구리 주인). `data/story/cast.json`에 추가. 톡 하면 랜덤 대사 6~8개.
   - 의자 3개: 가진 친구 중 무작위 3명 (`FriendLook.sticker`). 톡 하면 한마디 (각 친구 `bonds`에서 짧은 대사 재활용).
   - 문가 손님: `economy.recruit` 중 `by == "treat"`이고 아직 없는 친구 하나 (f04 알록 = 간식A 10개, f07 노바 = 간식B 30개, f11 초침 = 간식C 50개). 뱃지는 "간식 n/N". 모이면 "간식 주기" → `meta.recruit(id)` → 합류 연출(H-4와 같은 연출).
   - 탭 3개:
     - **라멘:** `economy.buffs.menu`에서 `mode == "battle"`이고 `unlock_clears` ≤ 깬 판 수인 것.
     - **수련:** `train_up("hp")`, `train_up("atk")`, 비용과 상한(`train_cap`) 표시.
     - **포장:** `economy.shop`의 `start_*` (시작 아이템 구매 → 다음 판 시작 때 판에 깔림).
3. `meta.gd`에 버프 추가:
   - `data.buff = ""`, `data.free_bowl = 0`, `data.bowls = 0`.
   - `eat(id)`: 무료 그릇이 있으면 쓰고, 없으면 코인. 5그릇마다 간식 1개.
   - `_finish_route()`에서 토벌을 **처음** 깨면 `free_bowl += 1`.
   - 토벌 시작 때(`battle_game.gd` 시작 처리) `buff`가 있으면 적용하고 비움: `team_hp + 150`, 게이지 `need * 0.5`로 미리 채움.
4. 편성 화면(`scenes/app/prep.gd`): 먹은 라멘과 포장 아이템을 아이콘으로 보여 줌.
5. 가게가 처음 열릴 때 G의 스포트라이트로 "가게 버튼 → 라멘 탭 → 손님" 세 군데를 비춰 줌.

## F. 아이템·장애물 가독성 + 이펙트 화풍 맞추기 (P1)

### 증상
아이템이 터지는 게 밋밋하고, 연출이 게임 그림체와 안 어울림. 아이템과 장애물이 잘 안 보임.

### 원인
- 이펙트 텍스처가 범용 게임 파티클임 (`board_view.gd`·`fx_layer.gd`의 `"circle_05"`, `"star_06"`, `"flare_01"`, `"spark_05"`, `"smoke_04"`, `"magic_02"`, `"light_02"`, `"twirl_01"`). 반들반들한 빛 번짐이라 크레용/연필 공책 화풍과 겉돎.
  - 이미 만들어 둔 손그림 셰이더 `shaders/eraser_dissolve`, `ink_spread`, `line_boil`, `paper`는 판 연출에 거의 안 쓰임.
- 1판 목표인 지우개 가루(분홍 부스러기)가 연한 칸 위에서 일반 블록과 구분이 잘 안 됨.
- 아이템(지우개, 압정, 크레용, 비행기)도 얼굴 블록과 같은 크기·톤이라 판에서 눈에 안 띔.

### 할 일
1. **이펙트 화풍 교체** (`scenes/board/fx/fx_layer.gd`, `board_view.gd`):
   - 블록이 터질 때: `eraser_dissolve` 셰이더로 지우개에 문질러 지워지듯 사라짐 + 지우개 가루 몇 알 튐. 반짝 별 대신 연필 낙서 "슥" 표시.
   - 지우개(줄): 지우개 스프라이트가 지나간 자리에 문지른 자국이 남았다가 사라짐 (지금은 `spark_05`).
   - 압정(폭발): 별 빛 번짐 대신 **잉크 튐**(`ink_spread`) + 종이 조각 + 굵은 연필 "쾅!" 글자.
   - 크레용(무지개): 빛줄기 대신 크레용으로 죽 긋는 선. 선은 `line_boil` 셰이더로 꿈틀거림.
   - 비행기: 날아간 궤적을 점선 연필선으로.
   - 새 스프라이트는 손그림 PNG 8~12장 (낙서 폭발, 가루, 종이 조각, 효과음 글자 "펑/쾅/슥"). 그림 담당 작업 목록으로 따로 뽑아 둘 것.
2. **아이템 눈에 띄게** (`scenes/board/tile_view.gd`):
   - 아이템은 흰 스티커 테두리를 두껍게 + 그림자 + 천천히 숨쉬듯 커졌다 작아짐(1.0↔1.06, 1.6초) + 가끔 반짝.
   - 칸 배경에 은은한 노란 원.
3. **장애물 대비 올리기** (`scenes/board/tile_art.gd`, `art/tiles/*`):
   - 지우개 가루: 분홍이 아니라 **흑연 회색 덩어리 + 진한 외곽선**. 큰 가루(2번 맞아야 함)는 덩어리를 2단으로 쌓고 숫자 뱃지.
   - 포스트잇, 테이프, 잉크도 각각 모양으로 구분되게: 포스트잇은 접힌 귀퉁이, 테이프는 사선 줄무늬, 잉크는 퍼지는 가장자리.
   - 검사 방법: 판 스크린샷을 **흑백으로 바꿔서** 블록 5종, 아이템 4종, 장애물이 서로 구분되는지 확인.
4. 칸 배경(`cell_view`)을 지금보다 약간 진하게 해서, 연한 장애물이 묻히지 않게.

### 완료 기준
- 흑백 스크린샷에서도 장애물과 아이템이 한눈에 구분됨.
- 압정 폭발 화면 캡처를 봤을 때 범용 파티클 느낌이 아니라 공책 낙서 느낌.

## G. 튜토리얼 재설계 (P1)

### 증상
튜토리얼이 너무 텍스트 위주라 불친절함.

### 원인
- `scripts/app/tutorial.gd` `STEPS`가 쪽지 안내문 묶음뿐.
  - 1판: 3장 (첫 이동만 손가락 안내).
  - 2판: 아이템 4종과 조합 규칙을 쪽지 **2장 글**로만 설명.
  - 토벌 1판: 3장.
- 다른 칸을 어둡게 하는 하이라이트가 없음. 첫 수 말고는 강제 이동이 없음. 직접 만들어 보는 단계도 없음.
- 쪽지(`scenes/app/parts/tutor.gd` `show_tip`)가 화면 위아래를 덮어서 안내 대상(이동 수, 목표)을 가림.

### 참고 (chiikawa-match `js/tutor.js`)
- `Spot.show` (264~317): 대상만 남기고 주변을 어둡게. 캐릭터 얼굴이 달린 말풍선에 **한 문장**. 대상을 누르면 다음.
- `showHand` (204~222): 칸 A에서 B로 1.3초마다 쓱 미는 손가락 반복. 나머지 칸은 0.35 투명도로 어둡게.
- `Tutor.allow`: 안내한 수만 둘 수 있음.
- `lesson` (117~137): **아이템 종류마다 처음 만들 때** 정해진 판에서 직접 만들고 써 보게 함 (꿈의집 방식).
- 6초 동안 안 움직이면 힌트. 기능이 열릴 때는 그 자리를 비춰 줌.

### 할 일
1. **스포트라이트** (`tutor.gd`): `spot(target_rect, text, face_id)`.
   - 어두운 막(검정 65%) + 대상 사각형만 뚫림. 셰이더 하나로 둥근 사각 구멍, 또는 패널 4장.
   - 말풍선은 캐릭터 얼굴(그렌 또는 뚝딱) + 한 문장, 대상 바로 옆에.
   - 대상을 누르거나 아무 데나 톡 하면 다음.
2. **손가락 + 칸 잠금**:
   - `board_view.gd`에 `allow_only(a, b)` 추가: 그 두 칸 말고는 `_gui_input`에서 거부. 나머지 칸은 `modulate.a = 0.35`.
   - 손가락은 지금 `point_move`를 그대로 씀.
3. **아이템 레슨** (`data/puzzles.json`에서 해당 판에 `fixed_board` 지원 추가 → `board.gd` `create(spec)`에서 처음 몇 줄을 고정 배치):
   - 1판: 3매치 (지금처럼).
   - 2판: **지우개만.** 4줄을 만들게 하고 → 만든 지우개를 직접 밀게 함.
   - 3~4판 근처: 압정 (ㄱ·ㅗ 모양).
   - 5판 근처: 비행기 (네모 4개).
   - 7판 근처: 크레용 (5줄).
   - 9판 근처: 아이템끼리 합치기.
   - 각 레슨은 "만들기 강제 이동 → 생긴 아이템 비추기 → 쓰기 강제 이동" 3단계. 글은 단계마다 한 문장.
   - `tutorial.gd` `STEPS`의 `point`에 `"make:eraser"` 같은 새 종류 추가.
4. **글 줄이기**: 단계마다 **한 줄 15자 안팎**. 예:
   - "옆이랑 쓱 바꿔 봐" / "이 숫자가 목표야" / "이건 남은 이동"
   - 속성 상성처럼 긴 설명은 그림 한 장(불꽃→새싹→물결→불꽃 화살표)으로.
5. **멈춰 있으면 힌트**: 6초 동안 안 움직이면 둘 수 있는 수 하나를 살짝 흔들어 보여 줌 (`puzzle_stage.gd` `_hint()`가 있으니 타이머만 연결해서 확인).
6. 기능이 열릴 때(친구 2판, 가게 4판, 길드 6판, 뽑기 8판) 지도에서 그 버튼을 스포트라이트로 한 번 비추기.
7. (H와 연결) 프롤로그를 글만 읽는 게 아니라 **그렌 혼자 휘갈김을 지우는 미니 판(0판)**으로 만들면, 첫 3매치 튜토리얼 + 그렌이 주인공이라는 걸 동시에 보여 줄 수 있음. 강제 이동 3번, 판 크기 5×5.

### 완료 기준
- 1~10판 동안 글을 한 번도 안 읽어도, 손가락과 비추기만 보고 아이템 4종을 다 만들고 써 볼 수 있음.
- 안내 한 단계에 글이 한 줄을 넘지 않음.

- 지도에서 내 위치 표시도 그렌이 아니라 뚝딱 스티커임.

1. **기준 데이터 하나로**: 영입 조건은 `roster.json`의 `get`을 기준으로 함.
   - `MetaConfig._init()`에서 `economy.recruit`를 쓰지 말고 `roster.json`의 `get`으로 `recruit_by_id`를 만듦.

   - export가 덮어쓰지 않게 0번 규칙대로 처리.
2. **그렌, 피오를 진행 데이터에 추가**:
   - `friends.json`(또는 덮어쓰기 파일)에 그렌, 피오 항목 추가. `roster.json`에 `web` 연결.
   - 스킬은 `roster.json`의 `grenn_s1`(두 줄 지우기) 등을 `base_effects` 형식으로 옮김.
   - `starters: [그렌]`, `default_team: [그렌]`.
   - 판 블록 얼굴(`tile_friends`)에 그렌이 이미 있으니, 토벌에서 그렌 블록이 그렌 공격으로 이어지는지 확인.
3. **영입 일정을 스토리에 맞춤 (안)**:

   | 판 | 합류 | 계기 (판에서 직접 보여 줄 것) |

   | 시작 | 그렌 | 프롤로그 0판: 혼자 휘갈김 청소 |

   | 13판 뒤 | 휘리 | 구조 (그대로) |
   | 14판 뒤 | 마샬 | 피오 소꿉친구, 중간 보스 뒤 (그대로) |
   | 23 / 26 / 29 / 30판 | 향기 / 뽀득 / 보리 / 밀라 | 그대로 |
   | - | 칼라, 단풍, 포포, 롤로 … | **뽑기 또는 라멘 가게 손님 전용** (판 깨기 보상에서 뺌) |

   1장 동안 합류는 2명만 해서, 한 명 한 명 얼굴을 익힐 시간을 줌.
4. **합류 연출** (새 `scenes/app/parts/join_card.tscn`): 스토리 끝에 붙임.

5. 지도 내 위치 표시를 그렌으로 (`scenes/app/map.gd` 내 위치 스티커).

## I. 대사 다시 쓰기: 그렌 말투 (P2)

### 증상
늑대(그렌) 말투가 AI가 쓴 것 같음.

### 원인
`data/story/*.json`의 그렌 대사가 거의 전부 같은 틀임:
- **문장 끝이 거의 다 "~다." "~냐." "~라."** 예: "또 왔냐. 오늘만 벌써 세 번째다." "기사 아니다. 그리고 넌 누구냐."
- **격언과 규칙으로 받아치기**: "돈 안 되는 일은 안 한다. 이 장사 첫째 규칙이다." → "둘째. 지나갈 길은 치운다."
- **장면마다 한 줄 펀치라인으로 닫기**: "아저씨는 빼라니까." / "세지 마라." / "듣기는 했냐." 이게 장면마다 반복됨.
- 나레이션이 소설 클리셰: "그날 아침까지는 그랬다." "이름보다 등에 멘 대검이 먼저 알려졌다."
- 문장 길이와 리듬이 늘 비슷하고, 감탄사, 말 끊김, 얼버무림이 없음.

### 그렌 말투 가이드 (`docs/design/script-style.md`에 추가)
- 나이 든 전직 기사, 지금은 청소꾼. **귀찮아하는 반말.** "~다"체 대신 **구어 반말 "~어/~지/~거든/~잖아"**를 기본으로. "~다"는 진짜 단호할 때만 (한 장면에 많아야 1번).
- 말이 짧고 자주 끊김: "…", "됐어.", "아니 그게 아니라.", "하아."
- 격언, 규칙 번호, 대구 금지. 받아치기 개그는 **장마다 많아야 한 번**.
- 정은 말보다 행동으로 (지문 `emote`, `hop` 등으로). 말로는 끝까지 인정 안 함.
- 같은 말버릇은 장마다 한 번까지. 입버릇은 따로 정해 두고 아껴 씀 (현재 메모: 10판에서 첫 등장).
- 나레이션은 한 장면에 2줄 이내. 상황은 그림과 지문(`shake`, 배경)으로 보여 주고, 글로 설명하지 않기.

### 예시: 1판 앞 (`ch01.json` `before:p001`)
지금:
> 그렌: 줄공책 들판이라더니 줄이 하나도 안 보이는군. 밭고랑마다 지우개 가루가 눈처럼 쌓였다.
> 뚝딱: 거기 칼 멘 아저씨! 청소꾼이지? …
> 그렌: 아저씨는 빼라. 청소꾼은 맞다.
> …
> 그렌: 돈 안 되는 일은 안 한다. 이 장사 첫째 규칙이다.
> 뚝딱: 아, 그렇구나. 그럼 둘째 규칙은 뭔데?
> 그렌: 둘째. 지나갈 길은 치운다. 가루가 길을 막았으니 어차피 치울 거다. 너 때문이 아니고.

바꾼 예:
> 그렌: (가루를 툭 찬다) …줄공책 들판이라며. 줄은 다 어디 갔어.
> 뚝딱: 거기! 칼 멘 아저씨! 청소꾼 맞지? 그렇게 큰 칼 메고 다니면 청소꾼 아니면 허풍쟁이랬어!
> 그렌: 아저씨 아니고. …청소꾼은 맞고.
> 뚝딱: 난 뚝딱! 저 다리 보여? 휘갈김이 밤새 갉아 먹어서 반 토막 났어. 고칠 순 있는데, 연장이 전부 가루 밑에 깔렸어.
> 그렌: 그래서.
> 뚝딱: 파 줘! 다 고치면 아저씨가 제일 먼저 건너게 해 줄게.
> 그렌: 돈 안 되는 일은 안 해.
> 뚝딱: (시무룩)
> 그렌: 하아… 어차피 저 길로 가야 돼. 가는 길에 치우는 거야. 너 때문 아니고.
> 뚝딱: (폴짝) 그게 그거잖아!

### 할 일
1. 위 가이드를 `docs/design/script-style.md`에 반영.
2. 1~3장(`prologue.json`, `ch01.json`~`ch03.json`) 그렌 대사를 전부 다시 씀. 4장 이후는 1~3장 확정 뒤에.
   - 프롤로그 나레이션 7줄 → 3줄 이내로 줄이고 나머지는 0판(G-7)에서 보여 줌.
3. 합류 장면(H-3 표의 계기)에 맞춰 `after:p001`, `before/after:b001` 장면을 고침. 피오 합류를 `after:p002`에서 `after:b001`로 옮김.
4. 검수 방법: 그렌 대사만 뽑아서 문장 끝 분포를 셈 (`~다.` 비율 20% 이하 목표).
   ```bash
   jq -r '.scenes[].steps[] | select(.say=="grenn") | .text' data/story/ch0*.json
   ```

## J. 배경 채우기 (P2, 그림 작업 필요)

### 증상
배경이 텅 빈 느낌.

### 원인
- **퍼즐 화면**: 위 정보 칸과 판 사이에 펼친 빈 공책 그림만 있음 (390×844 기준 세로 약 140px). 그 위에서 움직이는 게 없음.
- **대화 장면** (`scenes/story/story_scene.gd`): 배경 명령이 없음. 지금 화면(편성 화면 등)을 어둡게 깐 위에 스티커만 올라감. `_apply()`의 명령이 `enter / exit / emote / shake / hop / say / narr / title`뿐.
- 치이카와 매치는 지역마다 배경 이미지(`assets/img/stage/s1~s10.jpg`)를 깔았음. 그래도 움직이는 요소는 없었음 → 두들은 여기서 한 단계 더 가자.

### 할 일
1. **퍼즐 화면 빈 공책 칸 채우기** (`scenes/app/puzzle_stage.tscn`):
   - 펼친 공책 두 쪽에 **장마다 다른 낙서 풍경**을 그림 (1장 줄공책 들판 = 밭고랑 + 다리 + 허수아비 낙서 …). 지도 그림을 장별로 잘라 재활용해도 됨.
   - 풍경 위에 **그렌 + 데려간 친구가 서 있음.**
     - 콤보 3 이상이면 폴짝.
     - 이동 3 이하면 걱정 표정.
     - 판을 깨면 만세.
     - 아이템이 터지면 놀람.
   - `story_actor`의 스티커와 표정을 재활용.
   - 낙서 요소 2~3개(구름, 새, 연필선)는 `line_boil` 셰이더로 꿈틀거리게. 아주 천천히 흘러가게 해서 "살아 있는 공책" 느낌.
   - 목표 지점과 휘갈김(적) 낙서가 공책 오른쪽에서 꾸물대게 하면 "지우는 중" 맥락이 생김.
2. **대화 장면 배경** (`story_scene.gd` `_apply()`):
   - `"bg"` 명령 추가: `{"bg": "ch01_field"}` → `res://art/story/bg/ch01_field.png`.
   - 배경이 없으면 그 장의 기본 배경 (`route.json` 장 id로 찾음).
   - 배경은 종이 질감(`paper.gdshader`) 위에 깔고, 바뀔 때 0.3초 크로스페이드.
3. 그림 작업 목록(장별 퍼즐 배경 30장 + 대화 배경)은 1~3장 먼저 (6~8장).

### 완료 기준
- 퍼즐 화면에서 판 위쪽이 비어 보이지 않고, 캐릭터가 판 상황에 반응함.
- 대화 장면이 다른 화면 위에 덮이지 않고 그 장 배경에서 진행됨.
